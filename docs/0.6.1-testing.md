# 0.6.1 聊天图片展示验证

## 修复内容

0.6.0 的真实聊天记录表明：生图已完成，工具返回了图片预览和原图路径，但助手最终只回复“已保存到作品库”。工具的 `image` 内容及编排工具的 `image()` 输出不能作为最终聊天图片已经展示的证据。

0.6.1 增加 `display.terminal`、`display.ready`、`display.markdown`，并在工具文本和 Skill 中要求最终回复直接插入图片 Markdown。未完成时继续查询，预览读取失败时仍返回原图 Markdown，不重新生图。

创建工具另外绑定独立 MCP App 创作卡片。卡片显示真实状态、耗时和加载动画，独立进行只读查询，完成后原位显示原图；支持放大和下载。图片查询工具不重复创建卡片。

## 真实宿主边界

模拟宿主验证的是 MCP 协议对接和卡片本身的显示、交互，不能等同于 Codex 主聊天气泡的视觉验收。实际是否展示内嵌卡片、展示在何处，由宿主支持决定。当前自动化工具禁止读取 Codex 主窗口，MCP Apps 浏览器也仅能读取已展开到侧栏的应用，不提供聊天内联卡片清单。

安装时会结束旧 Imageboard MCP 进程；已进行中的聊天可能保留旧连接并报告 `Transport closed`。重开 Codex 或重新连接 MCP 后加载新工具及卡片资源。没有卡片支持时仍使用文字进度和最终图片 Markdown。

## 复现验证

```sh
npm run build:ui
npm test
node desktop/self-test.mjs
node scripts/verify-chat-ui.mjs
```

打开 `http://127.0.0.1:47826`，依次验证开始生成、完成、模拟失败、下次读图失败及重新读取。可切换深浅主题和 360px 宽度。模拟任务保存在临时目录，停止脚本后清理；截图与下载检查产物在 `work/chat-card/`，不提交到仓库。

真实聊天验收：重开 Codex 后要求使用 Imageboard 生成图片，检查过程中是否出现卡片、完成后最终消息是否包含图片，而不是只有作品库提示。需要分别记录“工具返回成功”“卡片出现”“最终图片显示”三个结果。
